## Major issues encountered (chronological)

1. **`runpodctl` and `hf` install** — uv tool trampolines initially broken (stale Python registry from prior pyenv-win uninstall); resolved via `uv tool upgrade --reinstall --all`.
2. **`hf` deprecated** — switched POD-DEPLOY.md and bootstrap to `hf` from `huggingface-cli`.
3. **`bash scripts/deploy.sh` PATH issues** — Git Bash on Windows vs WSL bash had different `$HOME` / drive mounting. Added `where.exe` fallback + `wslpath`/`cygpath` translation. Eventually superseded by `scripts/deploy.ps1` (native PowerShell).
4. **PowerShell native-arg quoting** — internal `"` stripped from JSON `--env` arg. Fix: backslash-escape the env JSON before passing.
5. **`runpodctl datacenter list -o json` parsing** — `ConvertFrom-Json` in PS 5.1 collapsed the JSON array into a wrapping object (auto-projection bug). Fix: use `System.Web.Script.Serialization.JavaScriptSerializer`.
6. **Volume-name collision across DCs** — `lyra-workspace` existed in 4 DCs (Vlad's other projects share the name); `Select-Object -First 1` returned all 4. Fix: match by (name + DC), refuse multi-match without explicit DC.
7. **Volume-capable DCs subset** — only ~20 of 45 RunPod DCs support network volumes; auto-pick was selecting valid GPU stock DCs without checking volume support. Fix: hardcoded `$VolumeSupportedDCs` allowlist (derived from RunPod's API error message).
8. **First image tag didn't exist** — `runpod/pytorch:2.7.1-py3.10-cuda12.8.0-devel-ubuntu22.04` is not published. Switched to actual RunPod template image: `runpod/pytorch:1.0.2-cu1281-torch280-ubuntu2404`.
9. **Anaconda channel ToS** — required since 2024. Fix: auto-accept in bootstrap.
10. **Conda solver failed on cuda + gcc 13.3** — classic and libmamba both. Root cause: `nvidia/label/cuda-12.8.0` has no Linux package (Windows-only). Couldn't be fixed by trying alternate channels because Lyra needs gcc 13.3 + cuda 12.8 specifically and conda can't reconcile that combination.
11. **Realised the base image already has CUDA 12.8.1 at `/usr/local/cuda`.** Skip the conda CUDA install entirely, point CUDA_HOME at system. **This unblocked the deploy.** Logged as decision `bypass-conda` for future repos.

## Lessons banked

- Bypass conda when the base image provides what's needed (decision log entry created).
- PS 5.1 + ConvertFrom-Json on JSON arrays: use JavaScriptSerializer.
- PowerShell native-arg passing: explicit `\"` escaping for JSON args.
- RunPod: only ~20 of 45 DCs support network volumes; volume locks the pod to its DC.
- RunPod: image tags published in templates ≠ Docker Hub names you might guess; always check `runpodctl template search`.
