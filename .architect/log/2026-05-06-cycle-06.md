## ~11:05 UTC — edited install-pod-claude.sh + skeleton

Added an SSH key restoration block to the heredoc that generates init-pod.sh. Same block added to the parallel template at `agent-architect/patterns/runpod-persistent-gpu-pod/templates/install-pod-claude.sh.skeleton`.

The block:
- Reads `/workspace/.ssh-state/pod_id_ed25519` (persistent source).
- If `/root/.ssh/pod_id_ed25519` is missing or differs (`cmp -s`), `cp` over.
- `chmod 600` on the destination.
- If `github.com` not in `/root/.ssh/known_hosts`, run `ssh-keyscan` to add it.

Idempotency by design: the cmp guard makes cp a no-op when current; the grep guard makes ssh-keyscan a no-op when host is known.

## Reliability findings

- Direct file rewrite over re-running install-pod-claude.sh saves time and reduces surface for new errors when only one block of the install changes.
- `cmp -s` is the right idempotency primitive for "copy if different". `cp` alone is fine but doesn't telegraph intent.
- `ssh-keyscan -t ed25519,rsa github.com` returns both host key types in a few hundred ms; no need for a longer wait.
- The pod's `/root/.ssh/known_hosts` after first SSH-into from Vlad's local was minimal (1 entry, just for the inbound host) — confirming that without an explicit ssh-keyscan, every fresh pod boot's first git push would have failed on a host-key prompt.
